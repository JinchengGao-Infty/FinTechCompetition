# Bot 等待故障验收

2026-10-30，本地修复，未提交或推送。预览：`http://127.0.0.1:65321/showcase.html?session=budget30qa#/bot`。

## 已确认原因

当前页面实际显示两条问候及“连接超时或服务异常，未创建新任务”。对应两次上游请求分别在 30,313 ms、30,141 ms 超时，尚未获得 HTTP 状态，未进入工具执行或语音播放阶段。旧诊断的 request 阶段包含连接、发送与等待响应头，不能据此进一步断言 DNS、TLS、网络或供应商排队中的哪一项异常。

文字回复本来就不等待 TTS 完成，TTS 不是这两次失败的原因。另发现前端缺少整个请求的等待上限；后台代码刷新锁覆盖了网络调用，会使不同会话相互等待。

## 修复

- 前端以同一 35 秒期限覆盖连接检查、协议读取、请求及响应体读取；5 秒后提示仍在等待，可停止。超时释放输入和 pending 状态，保留手动重试，不自动重发。
- 停止与超时均拒绝迟到结果；旧请求不能清除或覆盖新请求。文字结果保存后独立启动语音，语音失败不阻止文字展示。
- 上游增加 30 秒总期限看门狗，关闭可中断的连接；成功前再次核对期限，超期结果不能被标为完成。操作系统不可中断的 DNS 等底层阻塞仍由前端期限兜底，不能承诺后台每一种系统调用都会恰在 30 秒返回。
- 模块刷新锁只覆盖固定模块刷新，不再覆盖独立会话的上游等待；同会话在途保护仍保留。诊断区分等待响应头与读取响应体，不记录请求正文或密钥。
- 通过既有正常请求刷新固定本地模块，未重启服务、迁移凭据或增加调试端点。

本次成功说明当前真实调用已恢复；不能证明外部模型服务的偶发超时被消除，也不能把单条查询通过称为全部业务验收。原故障的更细底层原因仍不可确定。未更改供应商、网络、模型、会话期限或凭据保存策略。
