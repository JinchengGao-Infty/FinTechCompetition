# Windows拒绝请求连接中止修复

本轮仅本地合成/mock验证，没有真实供应商请求、读取Key、重启主服务或修改网络配置。

## 根因与复现

上一轮全量测试在事件/语音的安全拒绝路径出现Windows10053，单独重复原两项用例24次均通过，说明原夹具整包发送时存在时序差异。

进一步用隔离HTTP服务，将请求头与合成请求体分开发送，中间间隔50ms：原server.py的/api/voice/tts与/api/demo/events均稳定复现10053。原代码安全校验拒绝后，没有读取已声明的请求体便返回并关闭连接；Windows可能因未读入站字节中止连接，客户端无法完整收到本应返回的4xx。这是应用层拒绝响应传输缺陷，不是放行了非法请求，也不是供应商限流或实际网络设置问题。

## 修复

错误reply在安全拒绝决定之后，仅丢弃未消费的、单一Content-Length且不含Transfer-Encoding的有界请求体。总大小最多64KiB，总等待250ms，用绝对截止时间避免逐字节拖延重新计时。内容不做JSON解析、不进入业务执行、不调用上游；大体积或歧义帧不尝试读取，保持关闭连接。payload记录已读取字节，JSON解析失败也不重复读。错误响应明确Connection: close。

同一隔离探针修复后完整收到语音400、事件401 JSON；带有效本地会话、但错误Origin/CSRF的新增测试分别严格断言语音400、事件403，同时断言上游与事件队列均未调用。原语音测试从“不等于200”加强为“等于400”，没有放宽拒绝断言。
