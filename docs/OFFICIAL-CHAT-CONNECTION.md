## 固定协议

- 官方中国站 `https://api.minimax.cn/v1/chat/completions`
- 精确模型 `MiniMax-M3.1-Flash`
- `reasoning_effort: low`，响应速度优先；该模型不能关闭 thinking。
- `reasoning_split: true`、`max_completion_tokens: 4096`（包含推理 token）。不传无效的 temperature、service_tier 或旧 DeepSeek 的 thinking disabled。
- 当前规划器等待完整结构化结果，再校验 JSON 和业务合同；推理内容不进入 UI、TTS 或执行器。截断或无效 JSON 不创建任务。
- 每次用户发送至多一次上游请求，无自动重试。429/503 的 Retry-After 和本地冷却继续生效。
- 对话请求发送当前输入及必要任务上下文；语音仍只发送脱敏 speak。两者不共用配置字段，不迁移 Key，不持久保存。

依据：[MiniMax 官方 OpenAI 兼容协议](https://platform.minimax.cn/docs/api-reference/text-openai-api)。文档于本日核实；未以 TTS speech 模型替代对话模型。
