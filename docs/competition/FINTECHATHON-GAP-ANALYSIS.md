# FinPilot 对照 FinTechathon 2026：差距分析与实施顺序

核验时间：2026-10-15（Asia/Shanghai）。方向：国内人工智能赛道。来源：[官方赛题解析](https://fintechathon.g-ican.com/#/)、[官方规则](https://fintechathon.g-ican.com/#/rule)；官网原文快照在 `official-20261015/`。下面优先级是项目评估，不是组委会评定。

## 判断

FinPilot 的优势是已有真正改变模拟银行状态的转账、申购、赎回及安全控制，已有账单分析和理财解释能力。适合从财富管理应用收敛为“能够理解、追问、核对、执行、恢复的银行助手”，而非继续堆叠问答页面。至少三类场景是硬要求；定时转账、AA、生日订花等细分例子是参考，不必第一轮全部铺开。

评分为任务完成 40%、安全合规 30%、创新体验 30%。最值得投入的是三场景可演示任务与安全证据，随后才是更多场景和视觉微调。

| 对照项 | 基线已有 | 具体差距 | 本轮/下一步 |
|---|---|---|---|
| 至少三类核心场景 | 转账、账单分析、理财 | 分散在记账/规划/投研入口 | P0：统一银行任务入口，复用三个场景 |
| 意图与追问 | LLM 多轮补槽、固定联系人与产品识别 | 只有最近消息，没有显式任务状态 | P0：持久任务 ID、槽位、缺项、版本、取消/恢复 |
| 正确工具执行 | 参数表单、确认、模拟回执 | 草稿与业务结果体验割裂 | P0：接原核对/MFA/回执；P1：任务与执行记录同步关联 |
| 账单可信性 | 汇总、趋势、分类变化、异常候选 | 通用聊天自由生成金额，无源记录展开 | P0：确定性事实和区间对比，整数分与证据 ID |
| 权限分级 | 日累计额度、确认、TOTP | 小额申购仍是黄色，不符本届红色要求 | P0：任何申购均红色，保留原硬限额与校验 |
| 错误恢复 | 未知结果暂停、只读核账、防重复执行 | 模型故障易直接报错；对话刷新丢失上下文 | P0：模型不可用状态、任务恢复；不自动重放资金请求 |
| 注入及越权防御 | 来源链、结构校验、参数绑定、回放测试、锁定 | 缺乏本届三场景统一攻击集和分层报告 | P1：建立新攻击集，报告未授权写入数及误拒率 |
| 复杂任务规划 | 单业务草稿、规划解释 | 无可执行 DAG，无多工具依赖补偿 | P1：选择一个真实复合场景，显式节点、取消、失败恢复和人工接管 |
| 生成代码隔离 | 不执行模型生成代码 | 尚无受监控代码沙箱 | 禁用该能力；若后续启用须先实现隔离、资源限制和审计 |
| 创新与可用性 | 小屏玻璃界面、白话解释、来源可核对 | 缺少真实用户任务效率数据 | P1：不少于两轮可用性测试，测完成率、追问次数、纠错成功率 |
| 部署与材料 | Python 一键启动、历史源码材料 | 旧工行杯定位、旧验证不能直接提交 | P0：独立项目与新说明；P1：更新 PPT/安全自评/部署包 |

## 实施路线

- **首轮（本次）**：新目录、隔离运行、统一任务入口、三类场景草稿/事实、任务恢复、申购 MFA、回归测试与真实模型联调。
- **第二轮**：优先补“分析账单→用户选择可支配金额→核对申购”的依赖流程，明确中断和恢复；账单异常应显示依据，不下欺诈结论。同步强化任务与实际交易回执的关联。
- **第三轮**：扩展评测矩阵（漏槽、纠正、口语、外币、同名人、注入、重放、跨会话、超时、服务重启）。分别记录确定性测试和真实模型测试，报告样本数、通过率、P50/P95；不能外推为官方得分。
- **提交准备**：≤200字简介、技术文档、安全自评、≤10分钟 PPT、源码 README/部署/测试/GitHub 地址；≤5分钟视频可选。先录真实运行流程，再生成定稿材料。

官网报名截止 **11月1日**、作品提交截止 **11月2日**，未公布具体截止小时。10月28日答疑适合确认官方银行API/SDK、统一工具协议、模型限制和隐藏评测，这些目前公开页面未提供。报名状态、团队成员资格和官方工作台提交需团队核对。

## 能力边界

目前仅单用户私人演示；用户在入口获得原型会话，不等于生产级银行身份认证。TOTP 为当前原型第二因素，尚非真实银行身份认证/短信/人脸系统。固定联系人、两款模拟产品、资金累计较保守（申购与赎回也计入累计）；卡片、订阅、定时/AA 业务暂不支持。模型与规则混合路由会在响应标明来源，不宣称所有理解均由模型完成。

现有现金流与模拟资金、个人登记资产互相隔离，不把本金划转记成收入。事实回答只说明账本已记录数据，不能证明全账户完整消费。任务状态不是资金授权，草稿完成不代表银行执行完成。
