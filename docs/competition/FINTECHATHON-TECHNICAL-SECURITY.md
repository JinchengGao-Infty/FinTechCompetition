# 首轮技术说明与安全自评（2026-10-15）

这是本届开发中的自评草稿，不能替代最终完整评测或官方审核。

## 数据路径

浏览器 `#/banking` → 同源 `/api/book/finance/bank-tasks` → 任务状态机 → 本地 LLM 意图草稿 / 确定性账单事实。资金草稿进入原参数表单 → 独立 `/operations/review` → 用户核对 → 必要时动态口令 → MOSAIC Guard 重新检查事实 → 持久模拟银行 → 回执或未知结果核账。模型不可直接调用授权接口，也不执行模型生成的代码。

任务存储于独立 SQLite，绑定会话，使用版本比较防止旧页面覆盖新状态，请求 ID 防止同一请求重复应用。页面刷新可恢复同一会话任务；过期会话不能接管旧确认。账单事实使用整数分，退款单列，非人民币及本金划转不会隐式转换为普通消费。源账单 ID 支持人工核对。

## 分级实现

| 操作 | 当前控制 |
|---|---|
| 查询余额/账单/持仓 | 会话内只读查询，无资金副作用 |
| 小额转账，日累计≤1000元 | 展示确切收款方和金额，独立参数绑定确认 |
| 转账日累计>1000元 | 参数绑定确认 + TOTP；仍受原型单笔/日硬限额约束 |
| 任意金额理财申购 | `configs/fintechathon_policy.yaml` 对产品资金账户的合资格转入强制红色；确认+TOTP |
| 赎回 | 沿用累计资金规则；不把本金算作收益 |
| 不支持业务/生成代码 | 无执行工具；需明确说明范围 |

比赛策略复制自第三方内核策略后在项目 `configs/` 单独维护，没有修改内核。新增申购规则保留身份、账户活跃、收款方、余额、累计额度全部前置条件；默认拒绝和风险只升不降不变。策略哈希绑定运行目录，版本变更不能直接套用旧运行状态。

## 已有与新增防护

- 模型草稿无资金权限，参数需用户重新提交；服务端校验金额、联系人/产品、适当性与余额。
- Cookie HttpOnly、SameSite Strict；写请求检查 Origin 与 CSRF。新比赛 Cookie 名隔离，避免同一服务器不同端口串会话。
- 每次确认绑定当前会话、完整参数和期限；TOTP 反重放、连续失败锁定；服务器发放授权凭据，前端不能制造。
- 金额和回执来自工具；执行前重查；结果未知先暂停，核账只读，不自动重发扣款。
- 三场景任务状态、账单事实不会改变模拟资金；乐观版本与幂等请求保护对话改口。
- 多轮文本包含的模型指令不是系统权限；实际银行执行仍经独立核对。攻击防御效果仍需下一轮量化，不声称覆盖所有注入。

## 已知风险与待补齐

1. 单用户原型入口不提供真实身份认证、多租户隔离或银行实名验证。当前部署限定开发服务器局域网演示，生产需 HTTPS、强登录和可信反向代理。
2. 没有接入官方银行API，模拟回执不代表真实资金到账；TOTP 配置与真实银行 MFA 仍有差距。
3. 新任务只负责草稿和只读分析，交易回执仍在原操作记录；跨任务 DAG、补偿、人工接管未完整实现。
4. 真实模型主要用于意图归类和补槽，账单计算为规则；复杂表达、长对话及跨年区间覆盖仍需扩展评测。
5. 原始账本/会话/密钥不进入源码包；部署目录需要持久化备份、审计日志保留与访问限制；尚无生产级运维审计。
6. 旧材料及旧评测不视为本次验证。最终应附三场景正常/失败/攻击矩阵，披露样本、模型版本和全部失败案例。
