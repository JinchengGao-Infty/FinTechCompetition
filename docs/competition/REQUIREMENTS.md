## 基本任务与场景

作品应完成自然语言意图理解、任务规划和银行业务执行，并提供用户可用的 APP、IM 等连接渠道。官网没有在公开规则中要求必须同时提供原生 APP 和 IM，不能把它解释成必须接入所有渠道。

**明确要求：至少覆盖六类核心场景中的三类。** 完整覆盖六类是鼓励项。完整赛题特别说明典型能力表仅作参考，因此不能把每一项示例都改写成逐项强制条件。

| 核心场景 | 官方给出的能力示例（参考） |
|---|---|
| 智能转账 | 按姓名、手机号或备注识别收款人；定时执行；AA 拆分收款 |
| 账单分析 | 分类汇总；发现异常交易；月度或年度报告 |
| 理财操作 | 推荐和比较产品；风险评估；申购、赎回 |
| 卡片管理 | 申请；额度调整；限制或恢复交易；挂失 |
| 订阅 / 代扣管理 | 识别周期扣费；提醒续费；取消订阅 |
| 跨场景联动 | 围绕生日需求预留资金，并在指定日期安排鲜花、蛋糕等服务 |

仅列出入口或给出自然语言建议，不足以证明完成了“自主规划并执行业务”的任务。这个判断是本项目的验收解释；正式得分由组委会评审决定。

## 安全与任务规划

权限分级和安全机制在赛题中均标为高实现优先级。

| 权限等级 | 官方执行策略 | 官方典型操作 |
|---|---|---|
| 绿色 | 理解意图后自动执行 | 余额、交易记录、账单、理财收益等纯查询 |
| 黄色 | 展示详情并获得明确确认 | 日累计不超过 1000 元的小额转账；订阅查询 / 取消；虚拟卡申请 |
| 红色 | 强验证：人脸、短信验证码、U 盾等多因子认证 | 日累计超过 1000 元的转账；密码修改；挂失 / 解挂；理财产品申购 |

注意：官网明确把“订阅查询 / 取消”列在黄色，不能因为其他查询是绿色就自行更改；转账阈值按**日累计**判断，不是仅看单笔金额。边界 1000 元属于黄色。

其他核心技术要求：

- 账户信息与交易结果应有事实依据，避免幻觉。
- 权限控制应抵御 Prompt 注入。
- 关键操作保留决策链与执行日志。
- 连续失败或可疑行为触发安全锁定。
- 若生成并执行代码，应在受限、可监控的逻辑隔离环境内运行。
- 理解模糊、省略和隐含表达；复杂任务拆为有顺序依赖的 DAG。
- 执行支持中断、回退和人工接管。

公开规则要求红色操作强验证。项目中自建的演示验证码、模拟人脸或其他测试交互，只能标为模拟验证，不能直接宣称等同生产级多因子认证。

## 资格与作品归属

国内赛道面向中国内地及港澳台高校在读学生，以及在华高校就读的国际学生等。队员应全员为全日制在校本科生、硕士生或博士生。每队 2—5 人，可以跨校、专业或年级；每人只能参加一队。信息需真实、有效，作品须独立完成，不侵犯他人知识产权。

作品知识产权归参赛选手；主办方按规则享有赛事宣传使用权。参赛不收报名费。以上为规则摘要，报名时应阅读官方完整条款。
